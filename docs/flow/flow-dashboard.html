Screen 05 · Frontend Flow

대시보드 — 카드 하나가 훅 하나를 부르고, React Query가 요청을 합친다

대시보드는 카드 배치 3종(A·B·C) 중 하나를 그린다. 카드는 각자 자기 데이터 훅을 직접 부르고, 같은 쿼리키는 React Query가 하나로 합쳐 서버에는 한 번만 묻는다. 이 화면이 직접 쓰는 건 목표(PUT/DELETE /goals)뿐이고 나머지는 전부 읽기다.

F1 · Layers

사용자 조작이 서버까지 가는 길 — 이 화면의 파일들

모든 요청은 src/services/{domain}/{domain}.hook.ts → {domain}.service.ts → api.ts(axios, /api/v1, Bearer, 401 재발급 1회) 순서로 나간다. 화면 컴포넌트는 queryKeys.ts를 직접 import하지 않는다.

F3 · State

어디에 무엇이 있나 — 세 층의 상태

AppState (인터랙션)

  • dashboardLayout 'A'|'B'|'C' — 초기값은 localStorage에서 읽음
  • openModal 'addGoal' | 'institutions' · addGoalReturnTo null(대시보드) | 'custom'(설정)
  • reportOpen · reportPeriod(null = 현재 정산월) · reportSlide(0~4)
  • amountsHidden(기본 true) — 리포트 금액 숨김
  • datePickerPicked['goal'] — 목표 시점 달력

React Query (서버 캐시)

  • 기본 staleTime 30초, 4xx는 재시도 안 함, 5xx·네트워크만 1회
  • summary·allocation·trend·goal은 화면이 뜨는 즉시 요청(enabled 기본)
  • report는 오버레이가 열린 동안만(enabled: open) — 무거운 조회
  • goal preview는 입력이 유효할 때만, 400ms 디바운스, staleTime 60초
  • 서버 데이터는 AppState로 복사하지 않는다 — 캐시가 정본

localStorage (기기 힌트)

  • monit.dashboardLayout — 설정 → 일반의 레이아웃 버튼이 쓰고, 부팅 시 initialState가 읽음
  • 서버 설정에 필드가 없어 기기별로만 남는다. 다른 기기는 A
  • 접근 실패(프라이빗 브라우징)는 삼키고 'A'로 폴백
F4 · Journey

사용자는 이 순서로 쓴다

① 로그인 직후 — 라우트 '/' → '/dashboard'로 replace. AuthenticatedApp 청크가 내려오고 Dashboard가 마운트된다.
   레이아웃 A가 기본. 카드들이 동시에 훅을 불러 summary·allocation·trend·goal·distribution·institutions가 한꺼번에 나간다.

② 계좌가 하나도 없는 신규 사용자
   총자산 카드 → "계좌를 추가하고 총자산을 한눈에" + 점선 [계좌 추가] → AddAccountModal(openModal:'addAccount')
   리포트 배너는 숨김(hero.isEmpty). 목표 카드는 "아직 목표를 설정하지 않았어요" + [목표 설정].

③ 계좌를 막 만든 첫날
   summary가 0 → allocation 합계로 총자산을 보이되 증감 배지·올해 추이는 "자산 이력이 쌓이면" 문구.
   (서버 스냅샷 배치 이후부터 증감이 채워진다)

④ 평소
   총자산 + 이번 달 증감 → 목표 진행률(연간·월간) → 올해 추이 스파크라인 → 자산 구성 도넛 → 보관처 4곳.
   목표 카드 본문 클릭 → AddGoalModal(수정). 보관처 [전체 보기 ›] → InstitutionsModal.
   리포트 배너 → ReportOverlay(현재 정산월, 스토리 5장, ←→ 넘기기, 지난달 화살표, 이미지 저장·공유).

⑤ 배치를 바꾸고 싶으면
   설정 → 일반 및 디스플레이 → 대시보드 레이아웃 A/B/C → 즉시 AppState + localStorage → 대시보드로 돌아오면 바뀌어 있다.
   B: 총자산·증감·올해 추이를 딥카드 하나로. C: 이번 달 수입·지출·저축이 대표 카드(가계부와 같은 색).
F5 · Invalidation

이 화면에서 바뀌는 캐시 — 목표 저장·삭제

usePutGoal.onSuccess    → invalidate ['goal']  +  ['dashboard']
useDeleteGoal.onSuccess → invalidate ['goal']  +  ['dashboard']

반대로 이 화면이 **받는** 무효화(다른 화면의 쓰기가 대시보드를 흔든다):
  계좌 등록·수정·해지·잔액 정정   → ['dashboard'] ['goal'] ['asset'] …   (account.hook.ts)
  가계부 거래 등록·수정·삭제       → ['dashboard'] ['goal'] ['transaction'] ['account'] ['asset']
  매매·환전 등록·수정·삭제         → ['dashboard'] ['goal'] …
  엑셀 가져오기(importedCount>0)   → ['dashboard'] ['goal'] …
  연동 동기화                     → ['dashboard'] ['goal'] …
  월 시작일(monthStartDay) 변경    → 캐시 전체 무효화(설정 쿼리만 제외) — 정산월 의존 응답이 전부 바뀐다
목표(goal)를 계좌·매매·거래의 무효화 목록에 넣은 이유: GoalResponse.annual은 실시간 총자산 기준 진행률이라 계좌 하나만 추가해도 값이 달라진다. 빠지면 총자산 히어로는 즉시 갱신되는데 목표 카드만 옛 진행률로 남는다.
F6 · Report Overlay

월간 리포트 — 스토리 카드 5장과 달 이동

열기·닫기

  • ReportBanner 클릭 → { reportOpen:true, reportPeriod:null, reportSlide:0 }
  • period null = "현재 정산월" — 서버가 어느 달인지 정하고 reportYear/reportMonth로 알려준다
  • 닫기: X · Esc · 배경 클릭 → 세 필드 리셋. 다른 모달이 위에 떠 있으면 Esc·←→ 무시

쿼리 두 개

  • currentQuery = report(undefined) — 열려 있는 내내 살림. "앞으로 넘겨 현재 달에 닿았는가"를 이 응답으로 판정
  • periodQuery = report({year,month}) — 지난달을 볼 때만
  • 지난달 ← : displayed − 1개월. 다음 달 → : period + 1이 current와 같으면 null로 되돌림(미래 달 불가)
  • 보는 달 조회만 에러 화면. current 조회 실패는 첫 장 화살표 옆 작은 "다시 시도"

장 구성과 내보내기

  • ① 총자산 변화 → ② 자산 하이라이트 → ③ 소비 → ④ 전월·전년 비교 → ⑤ 요약(buildSummarySentence)
  • buildMonthlyReport: 비율 null은 '—', 금액은 움직였는데 0%면 '1% 미만'
  • 금액 숨김(amountsHidden)이면 비율만 — 값은 둘 다 만들어 두고 표시만 바꿈
  • [이미지로 저장]·[공유하기]: renderReportSlidePng → 1080×1920 PNG(html-to-image 지연 로드, 로드된 폰트 조각만 삽입) → 다운로드 / Web Share(미지원이면 다운로드)
F7 · States & CTA

카드마다 "로딩 → 에러 → 빈 상태 → 정상" — 문구와 버튼까지

모든 카드는 같은 순서로 분기한다. 로딩이면 '—'(컨테이너에 aria-busy), 에러면 error.message를 작은 빨간 글씨(흰 카드 --down · 딥 카드 --deep-down)로, 데이터가 없으면 EmptyState 안내문(+ 필요하면 점선 CTA 버튼), 그다음 정상 화면이다. 아래는 카드별로 "빈 상태"의 정확한 문구와 버튼이 여는 것, 정상 화면 안에서 한 번 더 갈라지는 지점이다.

F8 · Pitfalls

함정 — 이 화면에서 실제로 틀렸거나 틀리기 쉬운 것

데이터 흐름

  • 카드가 자기 훅을 부른다. 레이아웃이 데이터를 불러 prop으로 내려주면 다른 레이아웃에서 재사용이 안 되고, 같은 쿼리를 합쳐 주는 React Query의 이점도 사라진다
  • summary 0 ≠ 계좌 없음. 스냅샷이 아직 없는 신규 사용자도 0이다. allocation 합으로 보완하고, allocation이 로딩 중이면 판정을 보류(isHeroPending)해 "빈 상태 → 실제 데이터" 깜빡임을 막는다. allocation 실패는 빈 상태가 아니라 에러
  • 증감 null은 0이 아니다. 기준 스냅샷이 없으면 서버가 null을 준다 → 배지 대신 "이력이 쌓이면" 안내
  • 목표 미설정은 404가 아니라 0으로 채운 200. 그대로 계산하면 "0원 초과"라는 거짓 배지가 뜬다 → isUnset으로 배지 숨김

추이 그래프

  • x축은 1~12월 달력 고정. 데이터 개수로 등간격 배치하면 8월까지의 데이터가 12월까지 늘어나 보인다. 점 x = 600 × (월 − 1) / 11
  • 한 달에 점이 여럿이면 마지막 값만, 날짜순 재정렬(서버가 정렬을 보장하지 않음). 값이 모두 같으면 가운데 평평한 선
  • unit=MONTH의 date는 말일이 아니라 데이터가 있는 마지막 날짜. "월말 값"이라고 적지 않는다. "N월 N일 기준"이 이 값
  • 예측선을 그리지 않는다. 마지막 데이터 달 이후는 음영만. 강조 달은 마지막 데이터 달이 아니라 오늘 달
  • y축 라벨은 formatKoreanUnits가 셋 다 '0'이면 원 단위로 대체(소액 구간)

배치·스타일

  • .rgrid-institutions와 .rgrid-cards를 같이 쓰지 말 것 — 둘 다 !important라 900px(1열)·767px(2열) 규칙이 충돌
  • B안 모바일의 Goal → Allocation 순서 반전은 CSS가 아니라 useIsMobile()로 JSX 순서를 바꾼다
  • 도넛은 앱 전체에서 두 곳(이 카드 · 주식 섹터). 다른 카드에 새로 만들지 않는다
  • RAMP 배열이 dashboardView·assetsView에 따로 있다. 한쪽을 고치면 다른 쪽도
  • cardStyles.ts(상수)와 shared.tsx(컴포넌트)를 나눈 이유 — 한 파일에서 둘을 export하면 Fast Refresh 린트 경고

설정·기기

  • 레이아웃 값은 이 기기 localStorage에만 — 다른 기기는 A. 저장 실패(사생활 보호 모드)는 삼키고 이번 세션만 AppState로 동작
  • reportPeriod는 열 때마다 null로. 지난달을 보다 닫고 다시 열면 "이번 달 리포트" 배너와 다른 달이 뜨는 것을 막는다
  • 결제 예정일은 표기용 근사값 — 서버가 실제 며칠에 청구하는지는 계약에 없다
  • 헤더 알림을 눌러도 대시보드로 이동하지 않는다. 리포트는 알림이 아니라 배너로만 연다
