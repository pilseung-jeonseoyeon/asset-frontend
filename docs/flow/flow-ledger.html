가계부 — "이번 달"은 정산월이고, 입력 폼은 닫아도 기억한다

가계부(/ledger)는 개요(수지 하이라이트 · 분류별 지출 · 고정지출·구독 · 저축률)와 내역(달력 + 거래 목록) 두 탭이다. 모든 "이번 달"은 달력 1일이 아니라 사용자 설정 월 시작일 기준 정산월이며, 거래 입력 모달은 열리는 곳이 셋이고 저장하지 않고 닫으면 초안을 보관한다.

F3 · Settlement Month

정산월 — 화면이 "이번 달"을 잡는 방법

정본   GET /users/me/settlements/current → { year, month, periodStart, periodEnd }   (useGetCurrentSettlement, staleTime 60s)
래퍼   useCurrentSettlementMonth() = 서버 응답이 있으면 그 값, 없으면 settlementMonthOf(오늘, settings.monthStartDay)
       — 응답 전에도 설정값으로 같은 규칙을 계산해 깜빡임을 줄인다. DEV에서 둘이 다르면 콘솔 경고.

라벨   정산월은 "시작일이 속한 달"로 이름 붙는다. monthStartDay=28이면 9/26은 정산 8월(8/28~9/27).
       settlementMonthOf(iso, d) · settlementPeriodOf({year,month}, d) · shiftYearMonth — src/utils/date.ts

내역 탭 커서
       ledgerCursorFollowsCurrent=true  → cursor = useCurrentSettlementMonth()   (앱 열 때 · '오늘로 이동')
       사용자가 달·주를 넘기면 false      → cursor = { ledgerYear, ledgerMonth }
       주간 뷰: ledgerWeekAnchor(월요일) · 소속 달 = 그 주 목요일의 정산월(monthOfWeek) · 주차 = weekIndexInMonth

월 시작일을 바꾸면 usePatchUserSettings가 캐시 전체를 무효화 → 요약·순위·달력·목표·대시보드가 전부 새 경계로 다시 온다.
F4 · Journey

사용자는 이 순서로 쓴다

① 들어오면 항상 개요 탭 — 세그탭 옆에 [수입][지출][저축][이체] 빠른 입력 버튼(탭 전환 없이 바로 적게)
   딥카드: 이번 달 수입·지출·저축 + 전월 대비 배지 + 저축률 · [이번 달|올해] · ‹ › 지난 정산월
   지출 그룹: 분류별 순위(막대·증감률) · 고정 지출 · 구독   /   저축 그룹: 저축률 링 · 월별 저축률 막대

② 거래 적기 — 버튼 → LedgerEntryModal(유형 탭 숨김)
   금액 → 내용(2글자부터 최근 6개월 비슷한 제목 칩 ≤3, 누르면 내용·분류·계좌만 채움) → 메모 → 카테고리(대분류·소분류) → 계좌(기관 아이콘, 지난번 계좌 기억) → 날짜 → [지출 저장]
   저축·이체는 출금계좌 + 저축/입금계좌 두 칸, 같은 계좌면 막음, 계좌가 하나뿐이면 저장 막고 안내
   계좌 0개면 칸 안 목록 맨 아래 [계좌 추가] → AddAccountModal → 돌아오면 적던 값 그대로

③ 실수로 닫았어도 — X·Esc·배경·스와이프로 닫으면 초안 보관. 같은 유형으로 다시 열면 "이어서 작성 중이던 내용을 불러왔어요" + [새로 작성]

④ 내역 탭 — [주간|월간] ‹ 2026년 9월 (8.28 – 9.27) › [오늘로 이동] + 빠른 입력
   달력 칸 클릭 = 그날 내역만(다시 누르면 해제) · 데스크톱 칸의 + / 모바일 "이 날짜에 거래 추가" · 검색창은 전체 기간
   목록 행 클릭 → 수정(프리필, 단건 재조회 없음) → [변경사항 저장] / [삭제] 확인

⑤ 고정 지출·구독 — [고정 지출 추가] → 이름 · 아이콘(팝오버 분류 탭) · 금액 · 카테고리 · 결제일(매월) · 시작 날짜(선택) · 결제수단 → 저장
   행 클릭 → 수정 / [종료] 확인 (서버 배치가 결제일에 거래를 만든다 — 프론트는 거래를 만들지 않는다)

  → ['transaction'] ['account'] ['asset'] ['dashboard'] ['goal']

  → ['share']                                     — 소유자 가계부에 저장되므로 내 transaction·account는 그대로

  → ['subscription']                              — 거래는 서버 배치가 결제일에 만들므로 transaction은 건드리지 않음

  → ['category'] ['transaction']                  — 목록의 subcategoryName이 달라질 수 있음

F6 · Rules

표기·입력 규칙

유형별 필드와 색

  • 수입(+, --inc-*) · 지출(−, --exp-*) · 저축(부호 없음, --sav-*) · 이체(부호 없음, --text-strong, 달력에선 ⇄)
  • 수입/지출: subcategoryId 필수, 상대 계좌 없음 · 저축: 둘 다 필수 · 이체: transferAccountId 필수, 분류 없음
  • 저축·이체의 '계좌' 칸 = transferAccountId(상대), '출금계좌' = accountId. 수정 프리필도 같은 매핑
  • ADJUSTMENT·EXCHANGE 행은 서버가 만든 것 — 목록에 오더라도 클릭해 수정하지 않는다

소분류 제출값

  • 화면엔 첫 대분류·첫 소분류가 기본 선택으로 보여도 state는 null일 수 있다 — 제출값은 보이는 값으로 채운다(SUBCATEGORY_REQUIRED 방지)
  • 수정 중인 거래의 소분류가 삭제됐으면(논리 삭제) 보이는 소분류로 저장하고 그 사실을 안내
  • 공유 계좌를 고르면 분류 조회가 소유자 것(/shares/accounts/{id}/categories)으로 바뀐다
  • 404 ACCOUNT_NOT_FOUND / SUBCATEGORY_NOT_FOUND는 그 목록을 refetch해 사라진 선택지를 치운다

0과 null 구분

  • 저축률: 수입 0이면 서버가 null → 링은 "수입이 없어 계산할 수 없어요", 막대 말풍선은 '—'
  • 증감이 작아 0.0%면 '(+0.1% 미만)', 0%는 부호 없음
  • 최근 6개월 평균은 수입 있는 달만 — 0%로 넣으면 막 시작한 사람이 '평균 2%'가 된다
  • 금액 입력 상한 1조 미만(MAX_KRW_AMOUNT) — 16자리 넘으면 JS가 끝자리를 잃는다

F8 · Pitfalls

함정 — 이 화면에서 실제로 틀렸거나 틀리기 쉬운 것

정산월·기간

  • 달력 월로 조회하지 말 것. todayYearMonth()나 yearMonthOf(날짜)로 year/month를 만들면 월 시작일이 1이 아닐 때 아직 오지 않은 정산월을 조회해 화면이 빈다. "이번 달"은 useCurrentSettlementMonth(), 임의 날짜는 settlementMonthOf
  • 기간 조건을 섞지 말 것. 주간·날짜 선택은 from/to만, 월간은 year/month만. 둘을 같이 보내면 달력 주와 정산월 경계가 충돌해 있어야 할 거래가 빠진다. 검색은 기간을 모두 뺀다. 달력(이체 조회 포함)과 목록은 반드시 같은 기간
  • 주간 뷰의 일별 요약은 정산월 단위로만. 한 주가 두 정산월에 걸치면 두 번 받아 합친다(dailyQueryB)
  • 주간 칸 라벨 기준(확인 필요). buildWeekCalendarRow는 monthOfWeek를 monthStartDay 없이 불러 M/D 표시를 달력 월로 정한다. 기간 라벨·목록 제목은 정산월 기준이라 월 시작일이 1이 아닐 때 어긋날 수 있다
  • 카테고리 상세는 항상 이번 정산월(확인 필요). 개요에서 지난달을 보고 있어도 상세는 {}로 조회해 순위 카드(지난달)와 어긋날 수 있다

계좌 방향·합계

  • 이체의 계좌 방향. 서버 accountId는 저축·이체에서 "출금 계좌"이고, 화면의 "저축계좌/입금계좌"(entryAccountId)가 transferAccountId다. 이름만 보고 entryAccountId → accountId로 보내면 방향이 뒤집힌다. 수정 프리필도 반대로 뒤집어 넣는다
  • 기간 합계는 수입·지출만. 달력 상단 합계와 sumCalendarTotals는 저축·이체를 넣지 않는다(사용자 결정). 칸에는 네 종류 모두 그린다
  • 합계는 응답이 아니라 그려진 칸을 더한다 — 눈으로 더한 값과 늘 일치시키기 위해
  • 이체 줄은 별도 조회. 일별 요약 API가 수입·지출·저축만 주므로 type TRANSFER·size 200으로 따로 받아 날짜별 합산. 200건 초과는 캡션

모달·상태

  • 모달은 언마운트되지 않는다. useState(검증 플래그, 삭제 확인창)와 mutation 에러는 닫을 때 직접 지워야 다음에 남지 않는다. 새 로컬 상태를 추가하면 closeModal/resetAndClose에도
  • 날짜 선택기 상태는 공유 객체. datePickerPicked·datePickerViewingMonth는 다른 화면 달력과 한 객체를 쓰므로 entry/recur 키만 갈아끼운다(통째로 덮지 않기 — 리듀서가 얕은 병합)
  • 초안은 AppState(메모리)에만 — 새로고침하면 사라진다. 수정 세션은 초안을 만들지도 지우지도 않는다
  • 유형은 수정할 수 없다. 바뀌면 필수/금지 규칙이 통째로 바뀌는데 선택값 리셋 흐름이 없다 — 삭제 후 재등록. 계좌는 바꿀 수 있다
  • ADJUSTMENT·EXCHANGE 행은 서버가 만든 것 — 목록에 섞여 와도 클릭·포커스를 막고 수정 모달을 열지 않는다(방어 코드)

전체 교체·서버 배치

  • PUT은 전체 교체. 거래는 memo를 빼면 null로 덮이고, 구독은 icon·startedAt을 빼면 null로 지워진다 — 수정 모달이 기존 값을 프리필하고 그대로 다시 싣는 이유
  • 구독 결제 거래는 서버 배치가 만든다. 프론트가 거래를 따로 만들지 않고, 구독 변경은 subscription만 무효화한다(transaction 아님)
  • 아이콘 팝오버는 position: fixed. 모달 패널에 overflow:auto가 걸려 있어 absolute 팝오버는 잘린다(usePopoverAnchor)
  • 메모 길이 제한(확인 필요). 입력칸에 제한이 없고 OpenAPI에도 최대 길이가 없다 — 서버 제한 확인
  • 추천은 브라우저 비교. 6개월·500건 범위를 넘는 오래된 제목은 추천되지 않는다
