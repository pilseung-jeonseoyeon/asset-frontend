재산 — 화면은 흐르고, 계좌 하나의 일은 모달 안에서 끝난다

자산 화면(/assets)은 탭 없이 한 화면에 자산 구성 카드 → 함께 보는 계좌 → 트리맵 + 유동성이 흐른다. 계좌의 등록·상세·수정·공유는 전부 항상 마운트된 모달이 맡고, 어느 모달이 열려 있는지는 AppState의 openModal이나 전용 id 필드가 정한다. 서버 데이터는 React Query 캐시에만 있고 AppState로 복사하지 않는다.

F3 · State

모달 열림을 정하는 필드와 "되돌아갈 곳"

openModal 하나로 여는 것

  • 'addAccount' AddAccountModal — 닫으면 openModal ← addAccountReturnTo(ledgerEntry·quickStock·exchangeAdd·addHoldings·fixedExpense 중 연 모달, 없으면 null)
  • 'editAccount' + editingAccountId EditAccountModal
  • 'realEstateSoon' 부동산 준비 중 안내
  • 닫을 때 항상 openDropdown:null도 함께 — 전역 드롭다운 스크림(z70)이 남지 않게

전용 id 필드로 여는 것

  • assetClassDetail AssetCategoryModal(z80)
  • accountDetailId AccountDetailModal(z90) — 자산군 목록 위에 겹침
  • shareMembersAccountId + shareMembersReturnTo('accountDetail'이면 뒤로 가기가 상세를 다시 연다)
  • sharedAccountDetailId 공유받은 계좌 상세
  • entryReturnSharedAccountId 공유 계좌에서 가계부 입력을 열었을 때 돌아올 곳
  • 이 필드들은 isAnyModalOpen()에도 들어 있어 알림 배너를 미루는 판정에 쓰인다

폼 상태는 두 곳에

  • accountForm(AppState) — 이름·유형·기관·초기잔액·이율·날짜·유동성. AssetCategoryModal이 자산군 프리셋을 미리 넣어 연다
  • 로컬 useState — 보유 종목 줄(holdings), 기관 '없음' 선택, 검증 플래그, 달러 입력 문자열, 연동 API 키
  • 모달은 닫아도 언마운트되지 않으므로 resetAndClose가 로컬 state와 mutation을 직접 되돌린다
  • datePickerPicked['addAccountOpened'|'addAccountMaturity'|'editAccount…']도 닫을 때 지운다
F4 · Journey

사용자는 이 순서로 쓴다

① 처음 — 계좌 0개
   자산 구성·분포·유동성 카드 모두 "등록된 계좌가 없어요" + 점선 [계좌 추가]. 부동산 칸은 '준비 중' 배지.
   [계좌 추가] → AddAccountModal: 유형 칩(현금 기본) → 이름 → 금융기관(목록 끝 '없음' 포함) → 현재 잔액 → 유동성 → [계좌 추가]

② 주식·가상자산 계좌를 만들 때
   유형 칩을 주식으로 → 본문 맨 위 점선 배너 "토스증권·키움증권을 쓰시나요? → 연동하기"
     ├ 연동: 기관 고르기 → 키 두 값 입력 → [연동하고 가져오기] → 결과 화면(계좌 자동 생성) → [확인]
     └ 수동: 달러 잔액 + 원화 잔액 두 칸, 보유 종목 검색 → 수량·평단가 → [추가] 반복 → [계좌 추가]

③ 평소 — 자산 구성 카드 클릭 → 그 자산군 계좌 목록(AssetCategoryModal)
   계좌 행 → 계좌 상세(총 평가액·원화/달러 예수금·보유 종목·최근 거래 5건) · 연필 → 계좌 수정 · [계좌 추가](유형 프리셋)

④ 계좌 상세에서
   연동 계좌면 [가져오기]로 재동기화 · 현금·예적금이면 "가족·연인과 함께 보기" [초대하기] / [관리] · 연필 → 수정(이름·유동성·잔액 정정·예적금 이율/날짜·해지)

⑤ 함께 보는 계좌(초대를 수락한 쪽)
   자산 화면 "함께 보는 계좌" 구역에 "OO님의 계좌"로 보임(총자산에 안 더함) → 상세에서 거래내역 10건씩 '더 보기' · EDITOR면 [수입·지출 기록] · [나가기]
F5 · Invalidation

쓰기 한 번이 흔드는 캐시

usePostAccount · usePatchAccount · useDeleteAccount (useInvalidateAccount)
  → ['account'] ['asset'] ['dashboard'] ['institution'] ['stock'] ['trade'] ['goal']
    institution: 활성 계좌 보유 여부가 바뀜 / stock·trade: 등록 시 holdings가 BUY 매매를 만들고 해지 시 함께 사라짐 / goal: 연간 진행률이 실시간 총자산 기준

usePatchAccountBalance (useInvalidateAccountBalance)
  → ['account'] ['asset'] ['dashboard'] ['goal']          — 가계부(transaction)는 무효화하지 않음: ADJUSTMENT는 목록·집계에서 서버가 제외

usePostConnection        → ['connection']                   — 아직 계좌·매매가 없음
usePostConnectionSync    → ['connection'] ['account'] ['asset'] ['trade'] ['stock'] ['dashboard'] ['goal'] ['transaction']
useDeleteConnection      → ['connection']                   — 서버가 계좌·매매를 지우지 않음

usePostShare · usePatchShare · useDeleteShare (useInvalidateShare)
  → ['share'] ['notification']                              — 초대·수락·해제가 알림 카드 상태를 바꿈

  → ['share']                                               — 소유자 가계부에 저장되므로 내 account·asset·dashboard는 그대로

  → ['notification'] ['share']                              — SHARE_* 알림은 공유 상태가 바뀌었다는 뜻
F6 · Rules

화면이 지키는 표기·분기 규칙

금액은 서버 값 그대로

  • 계좌 대표 금액 = totalValueKrw(예수금 + 보유 종목). balanceKrw만 쓰면 주식 계좌가 작게 보인다
  • 달러 줄의 원화 환산은 balances[].amountKrw — 프론트가 환율을 곱하지 않는다. exchangeRate는 "1달러 = N원 기준" 각주용
  • 자산군 비중·지난달 대비 증감은 서버 sharePercent·changeFromLastMonthKrw
  • 구성 줄(원화 예수금·달러 예수금·보유 종목)은 쪼갤 것이 있을 때만 — 없으면 라벨이 '현재 잔액'

로딩 · 에러 · 빈 상태

  • 로딩은 '—' 한 줄, 에러는 서버 message 그대로(빨강), 빈 상태는 안내문 + 점선 CTA
  • 보조 조회(연동 목록·공유 목록)는 실패해도 화면을 막지 않는다 — 배지·칸이 안 뜰 뿐
  • 계좌 상세 거래내역은 가계부·매매 중 하나만 실패해도 나머지를 보여주고 "일부 내역을 불러오지 못했어요"를 붙인다
  • 422 FX_RATE_NOT_FOUND(달러 계좌 등록)는 에러가 아니라 회색 안내

되돌리기 어려운 동작은 그 자리에서 확인

  • 계좌 해지 · 멤버 내보내기 · 공유 끄기 · 공유 나가기 — 새 모달 없이 인라인 확인 블록
  • 담아둔 종목이 있는데 유형 칩을 바꾸면 "N개가 사라져요" 확인
  • 보유 달러보다 많이 파는 환전은 막지 않고 확인만(주식 문서)
  • 연동 해제는 설정 → 데이터 관리에만 둔다(계좌 상세에는 가져오기만)
F7 · Validation & Errors

모달별 검증 규칙과 에러 문구 — 어느 입력에 무슨 말이 뜨나

검증은 타이핑 도중이 아니라 저장을 누를 때(또는 포커스가 빠질 때) 켜지고, 문구는 그 칸 바로 아래에 작은 빨간 글씨로 둔다. 서버 에러는 ApiError.code로 분기하되 전용 문구가 없는 코드는 서버 message(완성된 한국어 문장)를 그대로 보여준다. 422 FX_RATE_NOT_FOUND만 빨간 에러가 아니라 회색 안내다.

계좌 추가 — 자산 유형별로 뜨는 칸 (FORM_FIELDS 표 하나가 JSX와 검증을 함께 결정)

현금 (CASH)현재 잔액(₩)——있음—

칩을 바꾸면 이름·기관·원화 금액은 그대로 두고, 새 유형이 쓰지 않는 필드(달러 잔액 · 예적금 3필드 · 날짜 선택 값 · 담은 종목)만 비운다. 담아 둔 종목이 있으면 "○○(으)로 바꿀까요? 추가한 종목 N개가 사라져요" 확인 블록이 먼저 뜬다.

F8 · Pitfalls

함정 — 이 화면에서 실제로 틀렸거나 틀리기 쉬운 것

숫자를 다시 계산하지 말 것

  • 환율을 곱하지 말 것(이중 환산). 달러분의 원화 환산은 서버가 조회 시점 환율로 매번 계산한다. 계좌 등록의 달러 잔액, US 평단가는 달러 그대로 보내고 화면은 balances[].amountKrw를 쓴다. amount × exchangeRate로 다시 계산하면 서버 반올림과 어긋나 합계가 1원씩 틀린다
  • 코인 평단가를 달러로 받지 말 것. 서버 시세가 업비트 원화 마켓에 고정돼 있어 환율이 두 번 곱해진다
  • 잔액 정정 원화 칸을 합계로 채우지 말 것. balanceKrw는 원화 줄 + 달러 환산분이다. 기준은 accountBalanceOf(account, 'KRW'). 합계로 채우면 저장 때 달러 환산분까지 원화로 정정해 버린다
  • 서버가 주지 않는 값은 그리지 않는다. 원금 대비 수익률, 자산군별 수익률, 환차익은 응답에 없다 → 화면에도 없다('원금 대비 +N%' 배지 없음)
  • 공유받은 계좌는 내 총자산·구성에 더하지 않는다 — 서버가 GET /accounts·분포에 넣지 않으므로 프론트가 합산하면 안 된다

계약에 없는 화면을 만들지 말 것

  • 계좌 하나의 추이 그래프. GET /dashboard/trend?type=에는 계좌를 지정하는 파라미터가 없다 — 그 유형 계좌 전부의 합계라 "이 계좌의 추이"로 그리면 틀린 숫자. 자산군 상세의 "최근 6개월 추이"도 사용자 결정으로 없앴다
  • AssetClass 유니언에 부동산을 넣지 말 것. 서버에 생기기 전엔 도넛·트리맵·응답 파싱이 있지도 않은 값을 다루는 척하게 된다. 생기면 RealEstateSoonModal과 준비 중 카드를 지우고 다른 5개처럼 처리
  • 국내/해외 주식을 계좌 유형으로 가르지 말 것. STOCK 하나에 원화·달러 예수금과 국내·해외 종목이 함께 들어간다. 시장·통화는 종목 줄마다(DraftHolding.market) — 블록 전체에 한 번만 계산하면 애플 평단가가 원화로 저장된다
  • 연동 해제는 설정 → 데이터 관리 한 곳. 계좌 상세에는 '가져오기'만. 새 연동 등록은 계좌 추가 모달 안 하나

항상 마운트된 모달

  • 닫아도 언마운트되지 않는다. 이 폴더의 모든 모달에 로컬 state·뮤테이션 에러·날짜 선택 키를 닫을 때 직접 되돌리는 resetAndClose/closeXxx가 있다. 새 입력칸을 추가하면 초기화 목록에도 추가
  • if (!isOpen) return null을 파생 계산보다 앞에. 닫혀 있는데 계산이 돌다 예외가 나면 ModalErrorBoundary가 리셋해도 다음 렌더에서 다시 죽는다
  • '계좌 추가'를 열 때 프리셋을 빼먹지 말 것. accountForm: { ...BLANK_ACCOUNT_FORM, ...assetClassFormPreset(id) }가 없으면 기본값 CASH로 열려 주식 칸에서 만든 계좌가 현금으로 저장된다
  • 수정 폼 초기값은 effect에서. 렌더 도중 setState하면 경고 + 루트 전체 리렌더. 서버 데이터를 AppState에 복사하지 않는 규칙의 예외로 허용된 자리

보유 종목 담기·연동

  • 줄 구분은 stockId가 아니라 rowKey. 같은 종목을 평단가를 나눠 두 줄로 담을 수 있어서, stockId로 지우면 두 줄이 함께 사라진다
  • key={markets.join(',')}로 통째로 재마운트. 안 그러면 고르던 주식 한 줄이 가상자산 계좌에 남는다
  • API 키는 로컬 state에만. AppState에 넣지 않고 등록 성공 즉시 지운다. 가이드 링크는 새 창(target=_blank + noopener) — 같은 창 이동이면 입력 중이던 키가 날아간다
  • 배너의 기관 나열은 지원 기관만(providerLabelsFor). KB증권을 불러 놓고 들어가서 막히면 약속을 어기는 셈
  • AddAccountModal의 환율 미수집 문구는 아직 "해외주식 계좌" — 국내·해외가 STOCK 하나로 합쳐지기 전 용어(핸드북 지적)
