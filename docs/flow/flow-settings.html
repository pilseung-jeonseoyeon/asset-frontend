이 문서는 설정 화면(/settings)의 모달 4개뿐 아니라 앱 부팅·세션 복원·로그인·회원가입(AppShell · Auth), 계정 모달(사이드바 아바타), 알림(SSE · 배너 · 패널), 엑셀·연동·공유 관리를 함께 다룬다. 전부 "어느 화면에 있든 같은 방식으로 도는" 것들이다.

F1 · Layers

인증 게이트와 세 층의 상태

액세스 토큰은 메모리(Zustand)에만 — localStorage에 넣지 않는다. 새로고침하면 refresh 쿠키로 한 번 되찾아온다. 로그인 전에는 Auth만 마운트해 401이 무더기로 나가지 않게 한다.

F3 · Auth Store

인증 상태 — 경쟁을 막는 두 장치

status: 'unknown' → (refresh 성공) 'authenticated' | (실패·타임아웃) 'anonymous'
                  ← signIn(로그인·온보딩 완료)                 ← signOut(로그아웃·재발급 실패·탈퇴 성공)

manualAuthPending  — 로그인 폼 제출 순간 true. 첫 방문자에게 로그인 화면을 먼저 띄우기 때문에 "A로 로그인 중인데
                     백그라운드 refresh가 예전 쿠키(B)로 성공"하는 경쟁이 실제로 가능 → 이 동안 applyRefreshedToken은 무시(false)
authGeneration     — signIn·signOut마다 +1. refresh는 요청 시작 시점의 세대를 기억했다가 응답 때 같을 때만 반영
markAnonymous      — 이미 authenticated면 내리지 않는다(수동 로그인 성공 → 뒤늦은 부팅 refresh 실패가 튕기지 않게).
                     sessionInvalid(401/403)일 때만 seenSession 힌트를 지운다 — 타임아웃·5xx는 "모름"

hasSeenSession()   — localStorage 'monit.seenSession' = '1'. 토큰이 아니라 불리언 힌트라 저장해도 안전.
                     재방문자는 BootScreen, 첫 방문자는 곧바로 로그인 화면(401이 뻔한 refresh를 기다리지 않음)

로그인 성공·로그아웃·탈퇴 성공 → queryClient.clear() — 이전 사용자의 캐시가 남지 않게
F4 · Journey

사용자는 이 순서로 쓴다

① 처음 — 로그인 화면(왼쪽 브랜드 패널 + 오른쪽 폼). [회원가입] → 약관 동의(필수 3 + 선택 1, '보기 ›' 전문) → 이메일·비밀번호·이름 → [인증 메일 받기]
   → 6자리 코드(붙여넣기·자동완성) → [인증 완료] → "프로필을 확인해 주세요"(이름 첫 글자 아바타) → [모닛 시작하기] → 대시보드

② 재방문 — 새로고침·재접속 시 로고(BootScreen) → 보던 화면 그대로(URL 유지). 쿠키가 끝났으면 로그인 화면, 다시 로그인하면 /dashboard

③ 쓰다가 토큰이 만료되면 — 요청 하나가 401 → 자동 재발급 → 원래 요청 재시도. 사용자는 모른다.
   재발급까지 실패하면 로그인 화면 + "세션이 만료되었어요" (다른 기기에서 탈취 감지면 "보안을 위해 모든 기기에서 로그아웃했어요")

④ 사이드바 아바타(모바일은 헤더) → 계정 및 프로필: 이름·마케팅 동의 변경 / 비밀번호 변경 / 로그아웃 / 탈퇴(비밀번호 재확인, 30일 유예 안내)

⑤ 설정 카드 4장
   일반 및 디스플레이 — 테마(라이트·다크·시스템) · 기준 통화(추후) · 대시보드 레이아웃 A/B/C · 알림(화면 안 팝업 · 맥·PC 알림 · 내용 보이기)
   데이터 관리 — 엑셀 가져오기(거래/계좌 양식 받기 → 올리기 → 결과) · 증권사·거래소 연동(가져오기·해제) · 내보내기(기간 → 거래/매매/계좌) · 백업·초기화(추후)
   자산·가계부 맞춤 — 카테고리 설정(소분류 추가·삭제) · 월 시작일 · 자산 목표 · D-Day 알림
   가족·커플 공유 — 받은 초대 · 내가 공유 중 · 참여 중

⑥ 알림 — 새 알림이 오면: 모닛을 보고 있으면 화면 위 가운데 배너(6초) / 다른 탭이면 맥·PC 알림(켰을 때) 또는 돌아왔을 때 "자리를 비운 사이 N개"
   벨 → 패널(오늘·어제·최근 7일… 묶음, 20건씩 '더 보기', 누르면 읽음+펼침, 공유 초대 카드는 [확인하기][거절])

F7 · Validation & Errors

폼별 검증 순서와 에러 문구 — 인증 · 계정 · 설정

인증 폼은 이메일 형식(EMAIL_PATTERN)·비밀번호 규칙(PASSWORD_PATTERN: 영문·숫자·특수문자 각 1개 이상, 8자 이상)을 프론트에서 먼저 보고, 서버 에러는 ApiError.message(완성된 한국어 문장)를 그대로 보여준다. 단 INVALID_INPUT은 friendlyInvalidInputMessage가 "○○ 입력을 다시 확인해주세요 — 길이나 형식이 맞지 않아요"로 바꾼다(필드명을 아는 경우만). 비밀번호는 어느 폼에서도 AppState에 넣지 않는다.

F8 · Pitfalls

함정 — 이 영역에서 실제로 틀렸거나 틀리기 쉬운 것

인증·세션

  • 가입 성공 ≠ 로그인. usePostSignup의 onSuccess에 signIn을 넣으면 온보딩 화면이 인증된 앱에 가려 보이지 않는다. 로그인 확정은 온보딩 "모닛 시작하기"에서만
  • 로그아웃과 탈퇴의 실패 처리는 반대. 로그아웃은 실패해도 세션을 끊고(onSettled), 탈퇴는 성공했을 때만(onSuccess). 통일하지 않는다
  • PUBLIC_PATHS는 앞부분 일치. /auth/password로 시작하는 경로는 전부 공개로 취급돼 토큰이 안 붙는다. 인증이 필요한 새 엔드포인트를 /auth/ 아래 두면 이 목록부터 확인
  • refresh는 single-flight. 두 번 나가면 서버가 REFRESH_TOKEN_REUSED로 전 세션을 끊는다. INVALID_REFRESH_TOKEN·REFRESH_TOKEN_REUSED 분기는 describeRefreshFailure에서만(응답 인터셉터 안에 두면 절대 실행되지 않는 코드)
  • 강제 로그아웃(인터셉터 signOut)은 queryClient.clear()를 부르지 않는다(확인 필요). 다음 로그인이 clear()하므로 남에게 보이진 않지만 그 사이 메모리에 이전 캐시가 남는다
  • authKeepLogin(확인 필요). initialState는 true지만 Auth 마운트 때 useGoAuthScreen이 false로 리셋해 실제 로그인 화면은 "로그인 상태 유지"가 꺼진 채 뜬다

항상 마운트된 모달

  • closeAndReset에서 mutation reset()과 로컬 state 초기화를 빼먹으면 다음에 열 때 지난 에러·성공 문구·삭제 확인 박스·평문 비밀번호가 그대로 남는다. 새 행·새 mutation을 추가하면 closeAndReset에도
  • Esc가 두 번 먹는다. 공용 Modal은 document 레벨에서 Esc를 받는다. 모달 안 인라인 입력(소분류 추가)에서 Esc로 입력만 취소하려면 stopPropagation(). AccountModal은 자체 스크림이라 Esc 리스너를 직접 붙이고 서브뷰에서는 한 단계만
  • 한글 IME와 Enter. 조합 중 Enter는 글자 확정용이라 keydown이 한 번 더 온다. isComposing/keyCode 229를 거르지 않으면 같은 이름으로 POST가 두 번 나간다(소분류 추가에서 실제로 서버 500). maxLength도 조합 중엔 잠시 넘을 수 있어 제출 때 길이를 다시 본다
  • 설정 조회 전에는 조작을 막는다. 캐시가 비어 있으면 낙관적 업데이트의 스냅샷이 없어 실패해도 되돌릴 수 없다. 테마·월 시작일·D-Day가 !settingsData일 때 비활성인 이유
  • 설정 행마다 usePatchUserSettings 인스턴스를 따로. 하나를 공유하면 두 행을 겹쳐 조작했을 때 먼저 보낸 요청의 실패 메시지가 사라진다. 겹치는 요청끼리는 고정 mutationKey로 알아보고 무효화로 수렴

테마·정산월·연동

  • 테마 롤백은 화면에서 하지 않는다. 캐시를 되돌리는 곳은 usePatchUserSettings 한 곳, 화면으로 옮기는 곳은 useSyncUserTheme 한 곳. 화면에 롤백 코드를 더하면 같은 로직이 두 곳으로 갈라진다. index.html 인라인 스크립트는 모듈을 import할 수 없어 readStoredTheme 로직을 복사해 두었다 — 테마 키·판정을 바꾸면 두 곳을 같이
  • 월 시작일 변경은 캐시 전체 무효화. 정산월 쿼리를 새로 만들면 queryKey에 {year, month}를 넣어야 이 무효화 뒤 올바른 기간으로 다시 받는다
  • 연동 해제는 여기서만. ConnectionsSection을 지우거나 숨기면 사용자가 등록한 API 키를 회수할 방법이 없어진다. 반대로 새 연동 등록을 여기 추가하지 않는다(진입점은 계좌 추가 모달 하나)
  • fxAutoRefresh는 화면에서 뺐다. PATCH 계약은 남아 있어 행 하나만 되살리면 다시 노출할 수 있다

알림·접근성

  • SSE 재연결은 직접. EventSource 기본 자동 재연결에 맡기면 1회용 티켓 때문에 401만 반복된다. onerror에서 닫고 새 티켓(3초 → 두 배씩, 최대 60초). 끊긴 동안의 알림은 서버가 다시 보내지 않으므로 재연결 시 목록을 다시 불러오는 동작도 지워선 안 된다
  • 읽음 처리는 read: true만. "읽음 취소"는 400. 필드명은 isRead가 아니라 read. 알림을 눌러도 다른 화면으로 이동하지 않는다(linkType/linkId는 쓰지 않음)
  • 페이지 크기(확인 필요). 패널 주석은 "20건씩"이지만 클라이언트는 크기 파라미터를 보내지 않아 서버 기본값에 달려 있다
  • 비밀번호는 로컬 useState에만. AppState는 모든 화면이 읽는 오래 사는 Context라 평문이 새어 나갈 통로가 된다. 이메일·이름·코드·동의만 AppState
  • 작은 접근성 구멍. 소분류 추가 입력칸 옆 취소 X는 span onClick이라 키보드로 못 누른다(Esc로는 취소됨). 삭제 X는 버튼으로 바뀌어 있다
