Screen 02 · Frontend Flow

주식 — 시세가 없을 수 있다는 전제로 그린다

주식 화면(/stocks)은 아홉 가지 조회를 한꺼번에 띄우고, 시장 탭(전체·국내·해외) 하나로 보유 종목·청산 종목·매매 내역을 함께 거른다. 이 화면의 핵심 함정은 시세 미확보다 — 평가액·손익·현재가는 전부 nullable이라 0으로 접지 않고 '아직 확보하지 못했어요'로 그린다. 쓰기는 매매·종목·환전 세 묶음이다.

F1 · Layers

이 화면을 이루는 파일과 상태

QuickStockModal·ExchangeAddModal은 폴더상 Assets/modals에 있지만 주식 화면과 헤더 퀵추가에서 연다. 모달은 전부 AuthenticatedApp에 항상 마운트.

F3 · Missing Price

시세 미확보 — 이 화면의 규칙

종목 하나가 null일 때

  • priceAsOf === null이면 valuationKrw·unrealizedPnlKrw·returnRatePercent·currentPrice·dayChangePercent가 함께 null
  • 카드는 priceMissing → 평가액 대신 총 매수금액(totalCostKrw) + "시세를 아직 확보하지 못했어요"
  • 원가가 0(증정주)이면 수익률만 null — 손익 금액은 계속 보여준다
  • 정렬·매도 드롭다운은 수익률 null을 맨 뒤로

요약 합산

  • 총 매수·총 평가·손익·수익률 네 지표는 전부 시세 확보 종목만으로 — "평가 − 매수 = 손익"이 화면에서 늘 맞게
  • 하나라도 빠졌으면 "일부 종목은 시세를 아직 확보하지 못해 … 제외했어요" 캡션
  • 전 종목 미확보면 네 값 모두 '—'
  • 총자산 대비 비중은 dashboard summary가 있어야 계산(없으면 캡션 숨김)

422 FX_RATE_NOT_FOUND

  • 해외 종목 보유 + 환율 미수집이면 holdings·groups·closed·exchanges/summary가 422
  • isExchangeRateMissing(error)가 true면 빨간 에러가 아니라 회색 안내
  • 매매 저장(POST/PUT /trades)에서도 같은 코드 → "아직 환율 정보를 가져오지 못했어요"
  • 환전 내역 모달은 summary가 아니라 목록(GET /exchanges)만 쓰므로 항상 열린다
F4 · Journey

사용자는 이 순서로 쓴다

① 보유 종목 0개
   요약 딥카드 "아직 보유한 주식이 없어요" + 점선 [매수] → QuickStockModal(매수)
   증권계좌가 없으면 계좌 칸에 "증권계좌를 먼저 추가해주세요" + [계좌 추가](주식 유형 프리셋, addAccountReturnTo:'quickStock')

② 매수 기록 — 국내/해외/가상자산 탭 → 종목 검색(없으면 '새 종목으로 등록' → 티커·종목명·섹터 → POST /stocks)
   → 수량·단가(종목 통화) → 수수료 → 계좌(기관 아이콘) → 매수일(미래 불가) → '예수금에서 차감' ON → [매수 기록 저장]

③ 이미 들고 있던 종목이 많으면 — [보유 종목 추가]: 계좌 먼저 → 기준일 → 종목 여러 줄 담기 → [종목 N개 등록] (POST /trades 순차)

④ 평소 — 시장 지표 → 요약(총 평가·매수·손익·수익률·보유 N개·총자산 대비) → 외화 카드 → 보유 카드(수익률 순, 현재가·전일 대비)
   → 청산 종목 → 매매 내역(행 클릭 → 수정·삭제) → 그룹별 수익률(섹터/국가) → 섹터 비중

⑤ 매도 — [매도]: 종목(보유) 드롭다운 → 계좌 고르면 "이 계좌 보유 N주" 상한 → 수량(초과 입력 자동 잘림) → 단가·수수료·증권거래세 → '예수금에 입금'

⑥ 환전 — [+ 환전 추가]: 원→달러/달러→원 → 달러 금액·환율(오늘 고시 환율 플레이스홀더) → 원화 환산 자동 → 주식 계좌 → 환전일
   [내역] → 환전 목록 → 행 → 수정(계좌 잠금)/삭제

⑦ 종목 이름·섹터를 잘못 적었으면 — 보유 카드의 섹터 라벨 → StockEditModal
F5 · Invalidation

쓰기 한 번이 흔드는 캐시

usePostTrade · usePutTrade · useDeleteTrade (useInvalidateTrade)
  → ['trade'] ['stock'] ['account'] ['asset'] ['dashboard'] ['goal']
    stock: 보유 수량·평단가 재계산 / account·asset·dashboard: settleCash로 예수금이 움직임 + 평가액 / goal: 실시간 총자산 기준
usePostTradesBulk → 같은 목록을 onSettled에서 한 번만 (줄마다 무효화하면 수십 번 재조회)

usePostStock  → ['stock']                          — 검색 결과·보유에 새 종목 반영
usePutStock   → ['stock'] ['trade']                — 종목명이 매매 내역에도 찍힌다

usePostExchange · usePutExchange · useDeleteExchange (useInvalidateExchange)
  → ['exchange'] ['account'] ['asset'] ['stock'] ['dashboard'] ['goal']
    환전은 계좌의 원화·달러 예수금과 해외 자산 평가액을 함께 바꾼다

이 화면이 **받는** 무효화: 계좌 등록(holdings → BUY 매매)·해지 → ['stock'] ['trade'] / 연동 동기화 → ['stock'] ['trade'] 외
F6 · Rules

표기·입력 규칙

통화·단위

  • 단가·평단가·현재가는 종목 통화(US = $, KR·CRYPTO = ₩). 평가액·손익은 원화(formatKrw, 소수 버림)
  • 수량 단위: 주식 '주', 가상자산 '개'. 소수 수량 허용(sanitizeDecimalInput 6자리, 보유 담기는 8자리)
  • 매매 내역 금액은 무채색·부호 없음 — 투자 거래는 '이체'로 취급(ds_rules §10-4)
  • 증감률은 '+1.2%' / '−1.2%'(U+2212), var(--up)/var(--down)

계좌 드롭다운

  • 매매: 시장에 맞는 유형만(KR·US → STOCK, CRYPTO → CRYPTO) — 서버의 400 INVALID_ACCOUNT_TYPE을 미리 막음
  • 환전: STOCK 계좌만 (달러를 담는 건 주식 계좌뿐)
  • 보유 추가: 주식·가상자산 계좌 전부, 고른 계좌가 검색 시장 범위를 정함
  • 기관 아이콘 + 기관명 보조줄(accountInstitutionMeta). 드롭다운 키는 모달마다 다름(stockAcct·holdingAcct·exchangeAcct)
  • 적합 계좌 0개면 빈 드롭다운 대신 [계좌 추가] → 유형 프리셋 + addAccountReturnTo

수정은 전체 교체

  • PUT /trades는 수량·단가·수수료·일자만 편집하되 tax·exchangeRate·memo를 그대로 되돌려 보낸다 — 빼면 0·null로 지워진다
  • PUT /exchanges는 금액·환율이 그대로면 서버 krwAmount를 그대로 보낸다(반올림 1원 어긋남 방지)
  • 종목·계좌·매수/매도 방향은 수정 불가 — 삭제 후 재등록
  • settleCash는 등록 전용(PUT에 없음)
F7 · Validation & Errors

모달별 검증 규칙과 에러 문구 — 그리고 누가 어떤 숫자를 계산하나

주식 화면의 숫자는 대부분 서버가 계산해 주고, 프론트는 문장으로 바꾸거나 여러 종목을 합산만 한다. 먼저 "누가 계산하나" 표를 두고, 그 아래 모달별 검증·에러 문구를 적는다.

표시 값 — 서버 값 그대로 vs 프론트 계산

표시 값누가어떻게
종목별 평가금액·평가손익·수익률서버valuationKrw · unrealizedPnlKrw · returnRatePercent 그대로
종목별 매수금액(원가)서버totalCostKrw 그대로 — 시세가 없어도 항상 있다. valuationKrw − unrealizedPnlKrw로 역산하지 않는다
현재가·전 영업일 대비서버currentPrice(종목 통화 — $77.00 / 77,000원) · dayChangePercent
요약: 총 평가금액·총 매수금액·평가손익프론트 합산시세가 있는 종목만 모아 각각 합계(전용 요약 API 없음). 같은 모수라 "평가 − 매수 = 손익"이 항상 맞는다. 시세 없는 종목이 있으면 캡션 "일부 종목은 시세를 아직 확보하지 못해 총 매수금액·평가금액·손익 계산에서 제외했어요"
요약: 평가 수익률프론트손익 합 / 원가 합 × 100. 원가 합 0이면 '—'
요약: 총자산 대비 비중프론트총 평가금액 / dashboard summary.totalAssetKrw × 100. 총자산 없거나 0이면 숨김. 분자는 현재 탭 보유분
그룹별 수익률(섹터·국가)서버/stocks/holdings/groups의 returnRatePercent. null이면 '—' + 회색(손실 빨강 아님), 정렬 맨 뒤
섹터 비중 %프론트그룹별 totalValuationKrw로 toPercentages(최대잔여법, 합 100). 7번째부터 모두 --ramp-6. 합 0이면 빈 배열 → 빈 상태
청산 종목 원금·회수금·실현손익·수익률서버principalKrw · proceedsKrw · realizedPnlKrw · returnRatePercent. 청산일 내림차순으로 와서 다시 정렬하지 않음
매매 행 금액프론트수량 × 단가(종목 통화). 수수료+세금 합이 0보다 클 때만 "수수료·세금 … 별도"
환전한 달러·원화 평가액·가중평균 환율·환차익·실현 차익서버heldForeignAmount · heldKrwValuation · weightedAvgRate(null이면 '—') · unrealizedGainKrw · realizedGainKrw. /indices의 USDKRW로 근사하지 않는다
계좌 달러 예수금 합계프론트 합산모든 계좌의 accountBalanceOf(a, 'USD')?.amount 합, 센트 단위 반올림. "환전한 달러"와 다른 숫자라 제목을 합치지 않는다
시장 지표 변동률서버 우선changeRatePercent가 있으면 그대로, 없으면(옛 응답) changeFromPreviousClose / (currentValue − changeFromPreviousClose) × 100. 변동액 null(USDKRW)·전일 종가 0이면 배지 숨김

QuickStockModal — 매수·매도 (파일은 Assets/modals)

상황문구 / 동작

F8 · Pitfalls

함정 — 이 화면에서 실제로 틀렸거나 틀리기 쉬운 것

null과 0

  • null을 0으로 접지 말 것. 시세 없는 종목의 평가값을 ?? 0으로 바꾸면 요약 합계에 섞여 틀린 숫자가 나오고, formatNumber(null)은 크래시한다. buildHoldingCards·buildPortfolioSummary가 명시적으로 거른다
  • null >= 0은 true. 그대로 계산하면 "+0.0%"가 찍혀 계산 불가가 손익 0처럼 보인다 → rate !== null && rate >= 0
  • 요약 네 숫자는 같은 모수. 시세 있는 종목만으로 평가·매수·손익·수익률을 계산해야 "평가 − 매수 = 손익"이 화면에서 맞는다. 대가로 총 매수금액이 실제 투입액보다 작게 보일 수 있어 캡션으로 밝힌다
  • 원가는 역산하지 않는다. 항상 서버 totalCostKrw. 수익률 정렬도 서버 returnRatePercent

서로 다른 숫자를 합치지 말 것

  • "환전한 달러"는 계좌에 든 달러가 아니다. heldForeignAmount는 환전 기록으로 사고판 달러의 순액이라 계좌 등록 때 넣은 달러·해외 매도 대금은 빠진다. 계좌 달러는 "계좌 달러 예수금 합계"로 따로 — 제목을 "총 보유 달러"로 바꾸지 않는다
  • 그룹별 수익률·섹터 비중은 탭을 따르지 않는다. 서버가 시장 필터를 받지 않아 항상 전체 보유 기준. 캡션 " · 국내·해외 전체 보유 기준"을 지우지 않는다
  • "전체" 탭에는 가상자산도 섞여 있다. all → market undefined. 가상자산 전용 탭은 없다
  • 코인은 KRW 고정. 업비트 원화 마켓 기준이라 USD로 등록하면 환율이 두 번 곱해진다(marketToCurrency)

캐시와 모달

  • 매매 내역은 최근 10건. GET /trades를 size 없이 전 건 받아 시장으로 거른 뒤 10건만 자른다(TRADE_HISTORY_LIMIT). 더 오래된 매매는 이 화면에서 수정할 방법이 없다 — 계좌 상세의 거래내역은 재산 문서
  • 수정 모달은 캐시에서 대상을 찾는다. TradeEditModal은 useGetTrades({}), StockEditModal은 useGetHoldings(undefined). 쿼리 키(파라미터)를 바꾸면 화면과 캐시를 공유하지 못해 요청이 한 번 더 나가거나 "찾지 못했어요"가 뜬다
  • 폼 초기값은 대상이 바뀔 때 한 번만. 세 수정 모달 모두 syncedId/loadedFor로 "이미 채운 id"를 기억해 입력 중 캐시가 다시 와도 덮지 않는다. 채우기 전 한 프레임은 '—'
  • 드롭다운 키 충돌. holdingAcct(보유 추가) · stockAcct(매매) · exchangeAcct(환전)를 따로 — 같은 openDropdown 키를 쓰면 한쪽을 열 때 다른 쪽도 열린 것으로 판정
  • "내역" 진입점과 매매 내역 섹션을 지우지 말 것. 잘못 입력한 매매·환전을 되돌리는 유일한 입구

등록·동시성

  • 보유 종목 일괄 등록은 POST /trades 순차 반복. 전용 API가 없고, 동시에 보내면 같은 계좌의 보유 수량·잔액 재계산이 경합한다. 계좌 생성의 holdings는 새 계좌에만
  • 실패 줄은 index로. 같은 종목을 두 줄로 담을 수 있어 stockId로 거르면 성공한 줄이 다시 남고 재시도 때 같은 매수가 두 번 기록된다(되돌리는 방법은 삭제뿐)
  • 평단가에 환율을 곱하지 않는다. 해외=달러, 국내·코인=원화 그대로
  • 응답에 있지만 안 그리는 값: avgCostPrice·avgCostPriceKrw·종목별 realizedPnlKrw — 카드에 없다고 서버가 안 주는 게 아니다
