# 증권사·거래소 API 키 연동(BYOK) 설계

작성일: 2026-08-29
상태: 구현 완료(2026-08-29). 가짜 키로 등록→실패 경로까지 확인했다. 실제 기관 키로 동기화를
성공시킨 적은 아직 없다.

## 1. 배경

사용자가 각 기관에서 **본인 명의로 직접 발급받은 API 키**를 앱에 등록하면, 서버가 그 키로 기관 API를 대신 호출해 계좌와 체결 내역을 가져온다(BYOK — Bring Your Own Key). 서비스가 기관과 계약하는 마이데이터 방식이 아니라, 개인 프로젝트가 허가 없이 합법적으로 할 수 있는 유일한 구조다.

사용자 입장의 흐름:

1. 기관 사이트에서 본인인증 후 API 키 무료 발급 (업비트는 **자산조회 권한만** 체크하면 됨)
2. 앱에 `provider` + 키 2개 등록
3. 동기화 버튼을 누르면 서버가 그 키로 기관에 접속
   - 첫 실행: **계좌를 자동 생성**(그 시점 예수금이 원금)
   - 이후 실행: 그 사이 발생한 체결을 매매 내역으로 추가

은행·카드는 키 발급 제도 자체가 없어 이 방식으로 불가능하며, 엑셀 가져오기로 대응한다(별건).

## 2. 서버 계약 (2026-08-29 라이브 OpenAPI 대조 완료)

### 엔드포인트

| 메서드 | 경로 | 설명 |
|---|---|---|
| `GET` | `/api/v1/connections` | 연동 목록. 앱 키는 마스킹(`acce****`) |
| `POST` | `/api/v1/connections` | 연동 등록 → 201 `ConnectionRes` |
| `POST` | `/api/v1/connections/{connectionId}/syncs` | 동기화 실행 → 201 `SyncRes` |
| `DELETE` | `/api/v1/connections/{connectionId}` | 연동 삭제 → 204 |

### `CreateConnectionReq`

| 필드 | 타입 | 필수 | 비고 |
|---|---|---|---|
| `provider` | `'UPBIT' \| 'TOSS_INVEST' \| 'KB_SECURITIES' \| 'KIWOOM'` | ✅ | **4종** |
| `appKey` | string (≤255) | ✅ | 발급받은 앱 키(액세스 키) |
| `appSecret` | string (≤255) | ✅ | 발급받은 앱 시크릿 |
| `accountId` | int64 | — | 생략하면 첫 동기화 때 계좌 자동 생성 |

### `ConnectionRes`

`id` / `provider` / `providerDescription`(기관 표시명, 예 `"업비트"`) / `appKey`(마스킹) / `accountId`(첫 동기화 전이면 null) / `lastSyncedAt` / `createdAt`

### `SyncRes`

`accountId` / `accountCreated`(이번에 계좌를 만들었는지) / `imported`(등록된 체결 수) / `skipped`(이미 등록돼 건너뜀) / `rejected`(검증에 걸려 거부됨)

### 확인된 제약

- 앱 시크릿은 서버가 암호화 저장하며 **응답에 절대 나오지 않는다**. 즉 등록 후 화면에서 시크릿을 다시 볼 방법이 없다 → 수정 UI를 만들 수 없고, 바꾸려면 삭제 후 재등록이다.
- 동기화는 **기존 데이터를 수정하지 않는다**(추가만).
- 연동을 삭제해도 **이미 만들어진 계좌·매매 내역은 남는다**.
- `providerDescription`을 서버가 내려주므로 기관 표시명을 프론트에 하드코딩하지 않는다.

### 에러 코드 (2026-08-29 백엔드 확정)

| 코드 | HTTP | 화면 처리 |
|---|---|---|
| `CONNECTION_DUPLICATE` | 409 | "이미 같은 키로 등록된 연동이 있어요" + 설정으로 안내 |
| `CONNECTION_NOT_FOUND` | 404 | "이미 해제됐을 수 있어요" |
| `CONNECTION_INVALID_CREDENTIALS` | 400 | **키 오류와 허용 IP 미등록이 같은 코드로 온다** — 두 가능성을 함께 짚어야 한다 |
| `CONNECTION_PROVIDER_NOT_SUPPORTED` | 400 | KB증권 전용. 애초에 고를 수 없게 막아 도달하지 않는 게 정상 |
| `CONNECTION_SYNC_FAILED` | 502 | 기관 장애 → 재시도 안내 |

문구는 `src/data/connectionView.ts`의 `describeConnectionError`가 정본이다. 서버 `message`도
사용자에게 보여줄 수 있는 한국어지만 "그래서 뭘 해야 하는지"가 빠져 있어 코드별로 다시 쓴다.

### 동기화 동작 (UI 문구에 반영됨)

- **첫 동기화는 계좌 생성 + 기준 시각 설정만 한다.** 체결을 가져오지 않으므로 `imported: 0`이
  정상이다 — 이 설명이 없으면 사용자가 실패로 읽고 키를 재발급하는 헛수고를 한다.
- 이후 동기화는 기준 시각 이후 체결만 추가하고, 기존 계좌·거래는 절대 수정하지 않는다.
- **연동 이전의 과거 체결과 기존 보유 종목은 들어오지 않는다** → 수동 등록 안내 필요.

### 기관 지원 현황

`UPBIT` · `TOSS_INVEST` · `KIWOOM`은 동기화까지 지원한다. **`KB_SECURITIES`는 등록만 되고 동기화가
`CONNECTION_PROVIDER_NOT_SUPPORTED`로 떨어진다**(공개 문서에 체결 조회 응답 필드 정의가 없어 백엔드
미구현). 화면에서는 칩을 "· 준비 중"으로 비활성한다 — 키를 다 발급받고 입력까지 마친 뒤 실패를
알게 되면 헛수고가 너무 크다. 근거는 `PROVIDER_META[p].supported`.

### 허용 IP

업비트·토스증권은 허용 IP 화이트리스트를 요구한다. 기관을 호출하는 주체는 사용자 브라우저가 아니라
**모닛 서버**이므로 등록할 값은 **서버 공인 IP `43.202.91.109`** 다. 사용자가 본인 IP를 넣으면 키가
맞아도 계속 실패한다 — 가이드 페이지 상단 딥카드에 복사 버튼과 함께 못박아 두었다.

## 3. 범위

### 포함

- `src/services/connection/` 도메인 신설(4개 엔드포인트)
- 계좌 추가 모달 안의 연동 진입 배너 + 연동 서브뷰(기관 선택 → 키 입력 → 동기화 결과)
- 설정 → 데이터 관리 및 백업에 연동 관리(목록·재동기화·해제)

### 제외 (사용자 결정 2026-08-29)

- **기존 계좌에 연동 붙이기**(`accountId` 지정). 이번엔 항상 생략해 계좌 자동 생성 경로만 쓴다. 이미 손으로 만든 증권 계좌가 있는 사용자는 계좌가 중복될 수 있으며, 계좌 상세의 "이 계좌에 연동 걸기"는 다음 단계 과제로 남긴다.
- 자동·주기적 동기화. 이번에는 사용자가 버튼을 눌러야만 동기화한다.

## 4. 진입점 배치 (사용자 결정 2026-08-29)

### 왜 계좌 추가 모달 안인가

- "계좌 추가" 버튼은 이미 **12곳**에 있다(자산 화면 2, 대시보드 1, 헤더 빠른추가 1, 각종 모달의 "계좌가 없어요" 자리 8). 버튼 옆에 진입점을 만들면 12곳을 모두 고쳐야 하지만, 모달 안에 한 번 넣으면 전부 커버된다.
- 지원 기관 4곳은 전부 주식(`TOSS_INVEST`/`KB_SECURITIES`/`KIWOOM`) 아니면 가상자산(`UPBIT`)이다. 자산 유형 칩이 **주식·가상자산일 때만** 배너를 띄우면, 은행 계좌를 만들려던 사용자는 이 기능을 아예 보지 않는다 → "내 은행은 없네" 실망이 구조적으로 발생하지 않는다.
- 첫 동기화가 계좌를 자동 생성하므로, 개념상 "수동 등록"과 같은 자리에 있는 것이 맞다.

### 배치 지점

`src/screens/Assets/modals/AddAccountModal.tsx` — **sticky 헤더가 아니라 본문(`flexDirection: column`) 맨 위, 계좌 이름 입력칸(`AddAccountModal.tsx:508`) 바로 앞.**

sticky 헤더에 두지 않는 이유: 모바일 바텀시트에서 스크롤 내내 화면을 차지한다. 본문 맨 위에 두면 스크롤과 함께 자연스럽게 사라지고, 아직 아무 값도 입력하지 않은 시점이라 "적던 게 사라진다"는 손실감도 없다.

## 5. 화면 설계

### 5-1. 연동 배너 (AddAccountModal 본문 최상단)

노출 조건: `selectedAssetClass === 'STOCK' || selectedAssetClass === 'CRYPTO'`

```
┌ ⌁ 키움·토스·KB증권을 쓰시나요? ────────┐   ← STOCK
│ API 키를 등록하면 계좌와 매매 내역이    │
│ 자동으로 채워져요                      │
│                        연동하기 →     │
└ (점선 테두리) ────────────────────────┘
```

- 가상자산 칩이면 문구를 "업비트를 쓰시나요? / API 키를 등록하면 계좌와 거래 내역이 자동으로 채워져요"로 바꾼다.
- 스타일: **점선(dashed) 보조 CTA 톤**(`AssetCategoryModal.tsx:108`의 점선 버튼, `Dashboard.tsx:56`의 `DASHED_CTA_STYLE_DEEP`과 같은 계열). 액센트 채움 버튼으로 격상하지 않는다 — 저장 버튼이 이미 액센트라 두 개가 경쟁하면 안 되고, 이건 선택적 대체 경로이지 주 동선이 아니다.
  ⚠️ `DASHED_CTA_STYLE_DEEP`은 `Dashboard.tsx` 모듈 내부 상수라 export되어 있지 않다. 구현 시 import하지 말고, 같은 시각 규격을 `AddAccountModal.tsx` 안에 지역 상수로 둔다(공용화는 이번 범위 밖 — 세 번째 사용처가 생길 때 판단한다).
- 터치 타깃 최소 44px.

### 5-2. 연동 서브뷰 (같은 모달 안에서 전환)

`AccountModal.tsx`의 서브뷰 패턴(← 뒤로가기 헤더 + 폼)을 그대로 따른다. **새 모달을 띄우지 않는다.**

**단계 1 — 기관 선택**

```
← 증권사·거래소 연동
─────────────────────────────
어디를 연동할까요?
[토스증권] [KB증권] [키움증권]
```

- 자산 유형이 `STOCK`이면 `TOSS_INVEST`/`KB_SECURITIES`/`KIWOOM` 세 개를 칩으로 보여준다. 칩은 `AddAccountModal`의 `chipStyle`을 재사용한다.
- **자산 유형이 `CRYPTO`면 후보가 `UPBIT` 하나뿐이므로 이 단계를 건너뛰고 곧바로 단계 2로 간다.** 칩 하나짜리 선택 화면은 의미 없는 탭을 한 번 더 요구할 뿐이다. 뒤로가기는 단계 2 → 계좌 추가 본문으로 바로 돌아간다.
- provider 목록은 프론트 상수로 갖되(`CONNECT_PROVIDERS`), 화면에 찍는 이름은 이 상수의 라벨이 아니라 서버 `providerDescription`을 우선한다. 단, 아직 연동한 적이 없는 provider는 서버 응답이 없으므로 이 단계에서만 상수 라벨을 쓴다.

**단계 2 — 키 입력**

```
← 업비트 연동
─────────────────────────────
① 업비트 → 마이페이지 → Open API 관리에서
  키를 발급받아 주세요. 자산조회 권한만
  체크하면 됩니다.

Access Key
[                              ]
Secret Key
[                              ]

🔒 입력한 키는 서버에서 암호화해 보관하고,
   다시 화면에 표시되지 않아요.

        [ 연동하고 가져오기 ]
```

- 발급 안내 문구는 provider별로 다르다(업비트/토스증권/KB증권/키움증권). 단, 기관 **표시명**은 서버 `providerDescription`을 쓴다.
- 입력값 검증: 둘 다 필수, 각 255자 이하, 앞뒤 공백 자동 제거(복붙 시 개행이 섞이는 실수가 잦다).
- 두 입력 모두 `type="password"` + `autoComplete="off"` + `spellCheck={false}`.
- 버튼을 누르면 `POST /connections` → 성공 시 곧바로 `POST /connections/{id}/syncs`를 이어서 호출한다(사용자에게 "등록"과 "동기화"를 두 번 누르게 하지 않는다).

**단계 3 — 결과**

성공:
```
✓ 키움증권 연동 완료
계좌를 만들고 매매 23건을 가져왔어요.
(이미 있던 2건은 건너뛰었어요)
        [ 확인 ]
```

- `accountCreated`, `imported`, `skipped`, `rejected`를 문장으로 조립한다.
- `rejected > 0`이면 "검증에 걸려 등록하지 못한 N건이 있어요"를 별도 줄로 덧붙인다(조용히 숨기지 않는다).
- `imported === 0 && skipped === 0`이면 "가져올 새 매매 내역이 없었어요"로 문구를 바꾼다.
- 확인을 누르면 모달 전체를 닫고 자산 화면으로 돌아간다.

부분 실패(등록은 됐는데 동기화가 실패한 경우):
```
연동은 저장했지만 가져오기에 실패했어요.
{서버 message}
[ 다시 시도 ]  [ 나중에 할게요 ]
```
연동 자체는 이미 서버에 만들어져 있으므로 **삭제하지 않고 남긴다.** "나중에 할게요"를 누르면 설정 → 연동 관리에서 재동기화할 수 있다는 안내를 덧붙인다.

### 5-3. 연동 관리 (설정 → 데이터 관리 및 백업)

`src/screens/Settings/modals/DataModal.tsx` — "엑셀로 가져오기" 행 아래에 새 행 추가. 클릭 시 인라인 아코디언으로 펼치는 기존 패턴을 그대로 쓴다.

```
▸ 증권사·거래소 연동
  API 키로 계좌·매매 내역 자동 등록
  ─────────────────────────────
  키움증권   acce****      [동기화] [해제]
  마지막 동기화 2026-08-29 14:02

  업비트     acce****      [동기화] [해제]
  아직 동기화하지 않았어요

  (없으면) 아직 연동한 기관이 없어요.
           계좌 추가에서 연동할 수 있어요.
```

**이 화면은 선택이 아니라 필수다** — 없으면 사용자가 한 번 등록한 API 키를 영영 지울 수 없다.

- "해제"는 되돌릴 수 없으므로 인라인 확인을 받는다(`AddAccountModal`의 `pendingAssetClass` 확인 블록과 같은 규격, 새 모달 금지). 확인 문구에 **"이미 만들어진 계좌와 매매 내역은 그대로 남아요"** 를 반드시 넣는다 — 서버 동작이 그러하고, 안 적으면 사용자가 자산이 사라질까 봐 해제를 못 한다.
- `lastSyncedAt`은 `src/utils/notificationTime.ts`의 상대시간 표기 규칙을 따른다.

### 무효화 대상

동기화 성공(`usePostConnectionSync.onSuccess`) 시 **계좌가 생기고 매매가 들어오므로** 넓게 무효화한다:

`qk.connection.all()`, `qk.account.all()`, `qk.asset.all()`, `qk.trade.all()`, `qk.stock.all()`, `qk.dashboard.all()`

(잔액·평단·손익을 매 요청마다 원장에서 재계산하는 백엔드라 좁게 잡으면 화면이 어긋난다 — `queryKeys.ts` 상단 주석의 근거와 같다.)

연동 삭제 시에는 `qk.connection.all()`만 무효화한다(계좌·매매는 남으므로).

### AppState

`src/state/types.ts`에 필드 2개 추가(기존 `accountModalView: string` 패턴을 따름):

- `connectView: string` — `'none' | 'provider' | 'form' | 'result'`, 기본 `'none'`
- `connectProvider: string | null` — 선택한 provider, 기본 `null`

**API 키 값은 AppState에 넣지 않는다.** 전역 상태에 두면 모달을 닫아도 메모리에 남고 다른 화면에서 읽을 수 있다. 비밀번호 폼(`AccountModal.tsx`의 password 뷰)과 동일하게 **컴포넌트 로컬 `useState`** 로 두고, 모달이 닫힐 때(`resetAndClose`) 명시적으로 빈 문자열로 지운다. 모달이 상시 마운트라 자동 언마운트가 일어나지 않으므로 이 초기화는 필수다.

## 7. 보안 고려

- 앱 시크릿은 로컬 스토리지·세션 스토리지·AppState 어디에도 저장하지 않는다. 입력 → 요청 바디 → 로컬 state 소거가 전부다.
- 입력 필드는 `type="password"`, `autoComplete="off"`, `spellCheck={false}`.
- 키가 담긴 요청·응답을 `console.log`로 남기지 않는다.
- 목록 화면은 서버가 마스킹해 준 `appKey`만 표시하고, 프론트에서 마스킹 로직을 따로 만들지 않는다.
- 발급 안내에 외부 링크를 넣는다면 `rel="noopener noreferrer"` + `target="_blank"`.

## 8. 테스트 관점 (러너 미구성 — 개발 서버 수동 확인)

- 자산 유형 칩을 현금 → 주식 → 현금으로 오갈 때 배너가 정확히 나타나고 사라지는가
- 담아둔 보유 종목이 있는 상태에서 배너를 눌렀다가 뒤로가기로 돌아오면 종목이 그대로 남아 있는가
- 키에 앞뒤 공백·개행을 붙여 넣어도 통과하는가 / 255자 초과 시 막히는가
- 등록은 성공하고 동기화가 실패했을 때 연동이 남아 있고, 설정에서 재동기화가 되는가
- `imported`가 0일 때, `rejected`가 0보다 클 때 각각 문구가 맞는가
- 모달을 닫았다 다시 열었을 때 이전에 입력한 키가 남아 있지 않은가 (상시 마운트라 실제로 위험)
- 연동 0건일 때 설정 화면의 빈 상태 문구
- 모바일 바텀시트에서 서브뷰 전환 시 스크롤 위치와 safe-area
- 연동 해제 확인 블록이 새 모달을 띄우지 않고 인라인으로 뜨는가

## 9. 남은 확인 사항

1. **실제 기관 키로 동기화 성공 경로를 아직 못 봤다.** 등록 실패(잘못된 키 → `CONNECTION_INVALID_CREDENTIALS`)는
   확인했지만, 성공 결과 화면(`accountCreated`/`imported`/`skipped`/`rejected` 문장 조립)은 실제 응답으로
   검증하지 못했다.
2. **업비트 키 1년 만료.** 만료되면 사용자가 재발급 후 연동을 해제하고 다시 등록해야 하는데, 화면이
   만료를 미리 알려줄 방법이 없다(`ConnectionRes`에 만료일 필드가 없다). 백엔드에 만료일 노출을
   요청할지 결정 필요.
3. **KB증권 지원 시작 시** `PROVIDER_META.KB_SECURITIES.supported`를 `true`로 바꾸고 가이드 페이지의
   "준비 중" 카드를 갱신하면 된다.
4. (다음 단계) 기존 계좌에 연동을 붙이는 흐름 — `accountId` 지정 시 계좌 유형이 맞지 않으면 어떤
   에러가 나는지.

## 10. 사용자 가이드

기관별 발급 절차는 앱 안이 아니라 별도 HTML 페이지에 있다(2026-08-29 사용자 결정) —
허용 IP·권한 범위·시크릿 1회 노출까지 모달에 다 적으면 정작 입력 폼이 화면 밖으로 밀린다.

URL은 `src/data/connectionView.ts`의 `CONNECTION_GUIDE_URL` 한 곳에만 있고, 기관 선택 화면과 키 입력
화면, 설정의 빈 상태 세 곳에서 새 창으로 연다(같은 창에서 이동하면 입력하던 키가 날아간다).
