이 프로젝트의 협업자는 개발 경험이 없습니다. 다음 원칙을 항상 지키세요.

- 전문 용어(커밋, 브랜치, 린트, 훅 등)를 쓸 때는 처음 한 번은 괄호로 짧게 풀어서 설명하세요.
- 되돌리기 어렵거나 위험한 작업(강제 푸시, 파일 대량 삭제, git 히스토리 변경 등)을 하기 전에는
  무엇을 왜 하려는지 먼저 평범한 말로 설명하고 진행 여부를 확인하세요.
- 작업을 마치면 코드 관점이 아니라 "화면에서 무엇이 달라지는지" 사용자 관점으로 1~2문장 요약하세요.
- 에러가 발생하면 원인을 있는 그대로 알리고, 사용자가 다음에 무엇을 선택하면 되는지 제시하세요.
- 불필요하게 길게 설명하지 말고, 확인이 꼭 필요한 순간에만 멈춰서 물어보세요.
